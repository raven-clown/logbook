# v0.2.0: trust policies and model-backed search

> Steps use checkbox (`- [ ]`) syntax for tracking. Follow the rules in AGENTS.md.

**Goal:** finish the trust rules the design promises and connect logbook to an embedding and extraction endpoint, so recall finds memories by meaning, `remember` can pull facts out of raw text, and near-duplicate or contradicting memories are linked without a `subject`.

**Architecture:** three new plugin points with registries, like `store`: `embed` (an `Embedder`, with the OpenAI-compatible client in `embed/openai`), `extract` (an `Extractor`, with `extract/openai`), and `vector` (an `Index`, with the in-process `vector/memory`). Vectors are stored in a new `embeddings` table so the in-process index can load them lazily and a background loop can fill in the ones that failed. `memory.Service` takes all three as optional options, so with none configured nothing changes. Outbound calls carry `X-Request-ID`, the W3C trace context and, when a client is set to forward it, the caller's OIDC token.

**Tech stack:** Go 1.26, `net/http`, `modernc.org/sqlite`, the existing `go.opentelemetry.io/otel` propagator. No new dependency.

**Spec:** `docs/design.md` sections 3 (Trust states, Conflicts, Links, Staleness), 4 (`remember` with `extract`, `recall`), 5 (Plugin interfaces, Storage, Recall ranking, transponder integration), 6 and 7. Contract: `mothership/CONTRACT.md` at a11a325, Identity, Headers, Storage (expand and contract migrations).

## Scope

The task listed five areas in priority order. Most of area 1 shipped in v0.1.0: verify, the five trust states, subject conflicts, the review-due staleness rule and recall ranking with trust weights. This plan takes what is left of area 1 and all of area 2 except pgvector, which needs Postgres.

In v0.2.0:

1. The verify policy per scope type (`writers` or `verifiers`), with `verifier` bindings counted.
2. A default `min_status` per scope type, so a team scope can return verified memories only.
3. Trust weights, review periods and `forget_retention` from the config file and environment.
4. Purge of forgotten memories after `forget_retention`.
5. Embeddings through any OpenAI-compatible `/v1/embeddings`, stored per model, with the in-process vector index, hybrid recall fused with reciprocal rank fusion, and a backfill loop for writes whose embedding failed.
6. `related` edges to near neighbours (similarity 0.80 or more, at most three) and the extractor contradiction check for memories without a subject (top three neighbours above 0.85, two-second budget).
7. `remember` with `extract: true` through any OpenAI-compatible `/v1/chat/completions` with a JSON schema response.
8. `logbook reindex`, and `/readyz` reporting the embedder and extractor.

Moves to v0.3.0, in this order: Postgres with pgvector and replicas; the admin API under `/admin/v1/` with `api/openapi.yaml`, `If-Match` versions, settings layering, per-scope overrides, the audit log, usage counts, the jobs table and the first-start admin key; limits from the shared profiles (`memory.items`, `memory.bytes`, `memory.writes`, `requests`); the shared metric names and CloudEvents usage events. Issue #7 (`valid_until` rule) stays open as a good first issue.

## Decisions

Recorded in `docs/design.md` section 12 as decisions 24 to 31 in the last task.

- 24. The caller's token is forwarded to the embedder and extractor only when that client sets `forward_token: true`, and a logbook API key (`lbk_`) is never forwarded. Otherwise the client sends its own `api_key`. This follows the contract's rule for airlock: forwarding to a service outside the stack is opt-in, and pointing logbook at OpenAI must not leak a caller's token. For transponder, set `forward_token: true`.
- 25. Vectors are stored per memory and per model key. The model key is the model name, plus `@<dimensions>` when `dimensions` is set, so changing either one starts a fresh set and `logbook reindex` drops the old ones.
- 26. The in-process index loads an organisation's vectors on its first search, not at startup, so one-shot CLI commands stay fast.
- 27. Neighbours for `related` edges and the contradiction check come from the new memory's own scope only, and must be active.
- 28. The backfill and purge loops run inside `logbook serve` and `logbook mcp`. They select their work straight from the memory tables, so v0.2.0 needs no jobs table. The jobs table arrives with the admin API.
- 29. The verify policy and default `min_status` are set per scope type in config. `verifiers` applies only to project and team scopes, since nobody can hold a `verifier` binding on a user scope. Per-scope overrides arrive with `PATCH scopes` in v0.3.0.
- 30. A recall request with no `min_status` takes each scope's default. An explicit `min_status: unverified` overrides a scope default of `verified`.
- 31. `/readyz` reports the embedder as `not configured`, `unknown` (before its first call), `ok` or `failing` from the outcome of its last real call, so a readiness probe never calls the model.

## Global constraints

- Pure Go, no cgo, no new module dependency. Unit tests use `httptest` and the fakes in `internal/testutil`, never the network. No bare `time.Sleep`.
- Budgets from the design: embedding on write 3 seconds, embedding a query 2 seconds, the contradiction check 2 seconds in total. A failed or slow embedding on write stores the memory without a vector and reports `degraded: ["embeddings"]`; a failed query embedding searches text only and reports the same.
- Thresholds: `related` at cosine similarity 0.80 or more, at most 3 per memory; contradiction check on the top 3 neighbours above 0.85.
- Extraction keeps at most 10 facts per call. Each is stored with `source: extracted` and its sentence as `evidence`.
- Migrations only add (expand and contract): `0003_embeddings.sql` adds a table and changes no existing column.
- Every table keeps `org_id`, `default` in every query.
- Config keys work from YAML and from `LOGBOOK_<KEY>__<NESTED>`. New value types from the environment: bool, int, float and Go durations such as `720h`.
- Memory content never goes into logs or errors from the new clients. Response bodies read from the endpoint are capped at 16 MiB.

## Review focus

1. An embedder that is down or slow on write: the memory is stored, `degraded` says so, and the backfill loop adds the vector once the embedder is back.
2. A caller's `lbk_` key or OIDC token must never reach an endpoint whose client does not set `forward_token`.
3. Vector hits must obey the same scope and filter rules as text hits: another user's memory, a forgotten memory, a wrong kind or tag, or one created after `as_of` never comes back from the vector side.
4. The extractor returns junk (not JSON, eleven facts, an empty fact, an unknown kind): bad facts are dropped or fixed, never stored as empty memories, and at most ten are kept.
5. A model or `dimensions` change: old vectors are never compared with new ones, and `logbook reindex` rebuilds them.

type Index interface {
